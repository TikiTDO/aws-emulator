# ListAWSDefaultServiceQuotas default rows misbound and re-worded for events firehose fms fsx gamelift glue imagebuilder

> _Note: this issue was identified against the code base at commit `9de0dc732b013e7abf09d4b752737b31a8a239ee`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
ListAWSDefaultServiceQuotas

## Description
ONE bundled issue with SEVEN causes (one ServiceCode each). All seven answer HTTP 200 with a well-shaped body, so the defect is purely the CONTENT of the default-quota catalog: rows are published under a QuotaCode that is not the code AWS publishes that quota under, Descriptions are re-authored in the emulator's own words instead of the service's, and some recorded QuotaCodes are not published at all.

THE GENERAL RULE (applies to all seven causes). For a given ServiceCode, ListAWSDefaultServiceQuotas returns one ServiceQuota row per QuotaCode AWS publishes for that service, and the row under a code carries THAT code's QuotaName, Value, Unit, Adjustable, GlobalQuota, Period, UsageMetric, QuotaContext and Description. The Description is the sentence the service itself publishes, verbatim — never a paraphrase, never another quota's sentence, and never absent when AWS publishes one. Smithy: ServiceQuota members QuotaCode @length 1..128 @pattern ^[a-zA-Z][a-zA-Z0-9-]{1,128}$, QuotaName, Value (QuotaValue, double, @range 0..10000000000), Unit, Adjustable (boolean, default false), GlobalQuota (boolean, default false), UsageMetric (MetricInfo), Period (QuotaPeriod), QuotaContext (QuotaContextInfo), Description @length 0..350. The model fixes only the row SHAPE; the per-code CONTENT is recorded behavior only, so each ServiceCode's recorded ListAWSDefaultServiceQuotas response is the reference. No status or error code diverges in any cause — expected 200, actual 200 throughout — so the requirement at stake is body content, not the error contract.
