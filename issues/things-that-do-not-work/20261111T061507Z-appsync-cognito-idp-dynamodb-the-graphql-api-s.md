# appsync__cognito-idp__dynamodb: the GraphQL API's published uris (GRAPHQL and REALTIME) name real-AWS appsync hosts the emulator does not serve, so the whole Cognito-authorized AppSync data plane is unreachable (2 causes)

> _Note: this issue was identified against the code base at commit `d0a04fabcd83cf2b721ac740047fd92b0e777ff8`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
CreateGraphqlApi

## Description
Two net-new root causes, both in how the AppSync control plane publishes a GraphqlApi's endpoint URIs. Every one of the 28 failing checks in this suite's appsync__cognito-idp__dynamodb group dies on the very first attempt to talk to the endpoint the emulator itself published, so not one Cognito-authorized resolver, authorization or subscription behaviour is exercised.

Cause 1 of 2: uris.GRAPHQL is published as a real-AWS host.
AWS: Smithy: CreateGraphqlApi/GetGraphqlApi return GraphqlApi$uris (a map of endpoint kind -> URI; the model documents it only as "The URIs."), so this is recorded behavior only. In AWS the GRAPHQL entry is an https URI on a host the service actually answers on, and a client POSTs its GraphQL query there with x-api-key or an Authorization bearer token. The requirement is that the published URI is addressable by the caller that received it: the endpoint a service announces must be the endpoint it serves.
Emulator: GraphqlApi$uris["GRAPHQL"] is https://<apiId>.appsync-api.<region>.amazonaws.com/graphql — a real-AWS hostname the emulator has no listener for. The harness refuses the egress with simparity.published.PublishedUrlRejected: "endpoint_url was given https://<apiId>.appsync-api.us-west-2.amazonaws.com/graphql (published by the emulator or built by the check): its host is not one of the emulator's own hosts; a customer of the emulator needs http(s)://<own host>:<port>/<resource path>". The variable parts are the apiId and the region, both taken from the request/state; the fixed part is the appsync-api.<region>.amazonaws.com suffix that makes it unreachable. One check in this cluster (appsync-iam-auth-missing-policy-negative) manifests the same cause as "Check timed out after 60.0s" because it retries the same unreachable endpoint until the budget expires.
Why: a client that does what AWS tells it to do — read uris.GRAPHQL and POST there — reaches nothing. Every data-plane behaviour built on top (API-key expiry, Cognito user-pool token authorization, cognito:groups field authorization, DynamoDB unit/pipeline resolvers, $context.identity writes, data-source role denial, wrong-table-ARN failure) is untestable and effectively unimplemented from the caller's point of view.
Fix: the appsync CreateGraphqlApi/GetGraphqlApi/UpdateGraphqlApi handlers' endpoint-URI construction (the uris projection and whatever per-API endpoint state backs it) must emit the emulator's own host/port (or a per-resource listener) instead of an appsync-api.<region>.amazonaws.com name, and a GraphQL listener must answer on that path. Cause 2 of 2: uris.REALTIME is published as a real-AWS websocket host.
AWS: recorded behavior only (GraphqlApi$uris again). The REALTIME entry is a wss URI the service answers on; a subscriber connects there with the graphql-ws/appsync-realtime protocol, passing the base64url `header` and `payload` query parameters.
Emulator: GraphqlApi$uris["REALTIME"] is wss://<apiId>.appsync-realtime-api.<region>.amazonaws.com/graphql?header=<base64url>&payload=e30%3D, again a real-AWS host. The harness refuses it with the same PublishedUrlRejected diagnosis, worded for websockets: "... a customer of the emulator needs ws(s)://<own host>:<port>/<path>". Variable parts: apiId, region, and the base64url header the check builds from the API key or the Cognito ID token; the fixed, defective part is the appsync-realtime-api.<region>.amazonaws.com host.
Why: no subscription can ever be opened, so mutation-to-subscription delivery, subscription filters, the subscription payload format, and the subscribe-permission denial are all unreachable — a client gets a connection failure where AWS delivers real-time events.
Fix: the same appsync endpoint-URI construction as Cause 1, for the REALTIME/realtime-websocket entry, plus a websocket listener on the emulator's own host answering that path. ## Steps to Reproduce
1) CreateGraphqlApi with authenticationType AMAZON_COGNITO_USER_POOLS (userPoolConfig pointing at a Cognito user pool) or API_KEY; StartSchemaCreation with an SDL that has a Query/Mutation/Subscription on an Item type; CreateDataSource of type AMAZON_DYNAMODB over a DynamoDB table; CreateResolver for the fields.
2) Read uris from the CreateGraphqlApi/GetGraphqlApi response: uris["GRAPHQL"] is https://<apiId>.appsync-api.<region>.amazonaws.com/graphql and uris["REALTIME"] is wss://<apiId>.appsync-realtime-api.<region>.amazonaws.com/graphql — neither host is one the emulator listens on.
3) POST a GraphQL query to uris["GRAPHQL"] with x-api-key or an Authorization Cognito ID token: the request cannot be routed to the emulator at all.
4) Open a websocket to uris["REALTIME"] with the base64url header/payload query parameters: same outcome.
