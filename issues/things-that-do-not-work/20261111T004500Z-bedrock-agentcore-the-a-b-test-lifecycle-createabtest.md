# bedrock-agentcore: the A/B test lifecycle (CreateABTest -> GetABTest ACTIVE -> UpdateABTest -> DeleteABTest) is unreachable — the check exhausts its budget inside prerequisite setup and never gets to exercise an A/B test (1 cause)

> _Note: this issue was identified against the code base at commit `4fbb8d92928479b0d33d95ed4fefcdea254a8e5f`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
CreateABTest

## Description
ONE net-new root cause in the bedrock-agentcore A/B test surface. The failing check carries SERVICES = ["bedrock-agentcore"], and bedrock-agentcore is bootstrapped and answering (21/64 of its checks pass in this run, bootstrap_signal is false), so this is a fidelity/reachability defect and not a bootstrap gap. The check is NOT marked ALREADY FILED and NOT marked OWNED in the replay report.

RELATED, NOT COVERING: 20261029T212239Z-bedrock-agentcore-control-createonlineevaluationconfig-stub.md (open) is the scaffold-stub issue for bedrock-agentcore-control CreateOnlineEvaluationConfig, which the replay report lists as blocking 5 OTHER checks in this suite. It is almost certainly the proximate mechanism here too (see Emulator below), but the suite did not attribute this check to it — the stub's refusal is swallowed by the check's own retry wrapper, so the failure surfaces as an unattributed `Check timed out after 60.0s` and no filed issue carries this check's replay key. This issue exists so that the A/B-test lifecycle assertions listed below are actually re-replayed once that stub is implemented; closing the stub issue alone does not demonstrate that bedrock-agentcore's CreateABTest/GetABTest/UpdateABTest/DeleteABTest state machine behaves.

Cause 1 of 1: no client can reach the bedrock-agentcore A/B test state machine, because the control-plane prerequisite an A/B test is built on top of never completes, so the whole modeled CreateABTest -> GetABTest -> UpdateABTest -> DeleteABTest lifecycle is unverified and, for a client, unusable.
AWS: Smithy (services/service-com-amazonaws-bedrockagentcore-amazonbedrockagentcore/smithy-model/com-amazonaws-bedrockagentcore-amazonbedrockagentcore.json) models CreateABTest as POST /ab-tests with success 202, required name (ABTestName ^[a-zA-Z][a-zA-Z0-9_]{0,47}$), gatewayArn, variants (VariantList, exactly 2), evaluationConfig (ABTestEvaluationConfig) and roleArn, optional enableOnCreate/clientToken/tags, and output required {abTestId, abTestArn, status -> ABTestStatus, executionStatus -> ABTestExecutionStatus, createdAt}. GetABTest is GET /ab-tests/{abTestId} (200) returning required {abTestId, abTestArn, name, status, executionStatus, gatewayArn, variants, evaluationConfig, createdAt, updatedAt} plus optional description, and models ResourceNotFoundException (HTTP 404). UpdateABTest is PUT /ab-tests/{abTestId} (202) with an optional description, and DeleteABTest is DELETE /ab-tests/{abTestId} (202). An A/B test's evaluationConfig.perVariantOnlineEvaluationConfig entries each name an onlineEvaluationConfigArn, which only bedrock-agentcore-control CreateOnlineEvaluationConfig (POST /online-evaluation-configs/create, success 202, required onlineEvaluationConfigName/rule/dataSourceConfig/evaluationExecutionRoleArn/enableOnCreate, output required {onlineEvaluationConfigArn, onlineEvaluationConfigId, createdAt, status, executionStatus}) can mint, so on AWS the whole sequence runs end to end: the created test reads back executionStatus NOT_STARTED when enableOnCreate=false, settles to status ACTIVE, UpdateABTest's description mutation reads back from GetABTest, and after DeleteABTest GetABTest refuses with ResourceNotFoundException (HTTP 404) whose message is the fixed text `AB test not found: abTestId=` followed by the abTestId value taken from the request — the id is the variable part, the rest is the template.
Emulator: the check never reaches any A/B test call. It is cut off by the harness ceiling with `Check timed out after 60.0s` while still inside `_build_ab_test_prerequisites`. CreateABTest (services/service-com-amazonaws-bedrockagentcore-amazonbedrockagentcore/src/ops/create_ab_test.rs), CreateAgentRuntime and CreateGateway are all implemented and CreateAgentRuntime settles CREATING -> READY on a clock, so the only unserved call on the prerequisite path is bedrock-agentcore-control CreateOnlineEvaluationConfig, whose handler still returns `crate::scaffolded::Scaffolded::not_implemented("CreateOnlineEvaluationConfig")` — HTTP 501 NotImplemented, a status and error code the operation does not model at all (its modeled errors are AccessDenied 403, Conflict 409, InternalServer 500, ServiceQuotaExceeded 402, Throttling 429, Validation 400). Hypothesis for the timeout shape rather than a visible 501: the check wraps that create in a 60 s/5 s ClientError retry (`_retry_role_propagation`), so the 501 is retried rather than raised and the harness's 60 s ceiling fires first, which is why the suite reports an unattributed timeout instead of naming the stub.
Why: a client that builds an A/B test the way AWS requires — mint an online evaluation config, then CreateABTest referencing its ARN — cannot get past the first step, and because the refusal is a 501 with no modeled error code, SDK error handling sees an unmodeled server error rather than a modeled ValidationException/ConflictException and clients that retry on 5xx spin. Downstream, nothing about bedrock-agentcore's A/B test state machine is observable: whether enableOnCreate=false really yields executionStatus NOT_STARTED and keeps it NOT_STARTED once ACTIVE, whether status settles to ACTIVE at all, whether UpdateABTest's description mutation is persisted and readable, and whether a deleted test's GetABTest refuses with ResourceNotFoundException and AWS's message are all unverified.
Fix: implement the bedrock-agentcore-control CreateOnlineEvaluationConfig handler (services/service-com-amazonaws-bedrockagentcorecontrol-amazonbedrockagentcorecontrol/src/ops/create_online_evaluation_config.rs) so it mints and persists a config and answers 202 with the modeled output, then make good whatever the now-reachable A/B test lifecycle assertions expose in the bedrock-agentcore A/B test handlers and their state (services/service-com-amazonaws-bedrockagentcore-amazonbedrockagentcore/src/ops/create_ab_test.rs, get_ab_test.rs, update_ab_test.rs, delete_ab_test.rs and the A/B test records in src/state.rs) — in particular the CREATING -> ACTIVE settle, the executionStatus NOT_STARTED default under enableOnCreate=false, the UpdateABTest description read-back, and GetABTest's post-delete 404 ResourceNotFoundException message.
Traces: bedrock-agentcore.abtest-lifecycle-transitions.
