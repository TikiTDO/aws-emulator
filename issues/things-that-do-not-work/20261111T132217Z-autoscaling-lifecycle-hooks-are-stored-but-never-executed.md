# autoscaling: lifecycle hooks are stored but never executed — no instance is ever parked in Pending:Wait/Terminating:Wait, and two PutLifecycleHook refusal messages are emulator-worded (3 causes)

> _Note: this issue was identified against the code base at commit `3f07c9f1d60993a38a36a4f215d4651495d2c52f`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
PutLifecycleHook

## Description
Three net-new root causes in the Auto Scaling lifecycle-hook surface. Cause 1 is the hook state machine; causes 2 and 3 are two separate refusal messages of PutLifecycleHook. A fixer must close all THREE before submitting.

Cause 1 of 3: a lifecycle hook attached to a group never holds a launching or terminating instance in a wait state, so the whole hook protocol (wait state, action token, heartbeat, CompleteLifecycleAction, DefaultResult-on-timeout) is unobservable. Failing check ids: autoscaling.lifecycle-hook-heartbeat-extends-timeout, autoscaling.lifecycle-hook-heartbeat-timeout-extension, autoscaling.lifecycle-hook-timeout-applies-default-result, autoscaling.lifecycle-hook-full-cycle, autoscaling.lifecycle-hook-full-lifecycle, autoscaling.lifecycle-hook-heartbeat-complete-order, autoscaling.lifecycle-hook-abandon-terminates-the-instance-instead-of-serving, autoscaling.complete-lifecycle-action-unknown-hook-rejected, autoscaling.complete-lifecycle-action-reused-on-a-consumed-action-rejected-and-the-instance-stays-waiting, autoscaling.e2e-scale-out-lifecycle-hook-scale-in-teardown, autoscaling.e2e-scale-out-lifecycle-hook-terminate-flow, autoscaling.e2e-scale-out-scale-in-lifecycle-hook-flow, autoscaling.deep-autoscaling-2-asg-enforce-terminate-hook-abandon-retain-keeps-instance-outside-desired.
AWS: Smithy (services/service-com-amazonaws-autoscaling-autoscaling-2011-01-01/smithy-model/com-amazonaws-autoscaling-autoscaling-2011-01-01.json) models the hook contract: LifecycleHook.LifecycleTransition doc "Valid values: autoscaling:EC2_INSTANCE_LAUNCHING | autoscaling:EC2_INSTANCE_TERMINATING"; LifecycleHook.HeartbeatTimeout doc "The maximum time, in seconds, that can elapse before the lifecycle hook times out. If the lifecycle hook times out, Amazon EC2 Auto Scaling performs the action that you specified in the DefaultResult property"; LifecycleHook.GlobalTimeout "the maximum time an instance can remain in a wait state"; LifecycleHook.DefaultResult "Valid values: CONTINUE | ABANDON"; CompleteLifecycleAction takes LifecycleHookName/AutoScalingGroupName (@required) plus LifecycleActionToken (@length 36..36) or InstanceId and a @required LifecycleActionResult; RecordLifecycleActionHeartbeat takes the same addressing and resets that countdown. The existence of a wait state is therefore required by the model: a launching instance held by an autoscaling:EC2_INSTANCE_LAUNCHING hook reports DescribeAutoScalingGroups -> AutoScalingGroups[].Instances[].LifecycleState == 'Pending:Wait' and leaves it only on CompleteLifecycleAction or on HeartbeatTimeout expiry (then DefaultResult applies); a terminating instance held by an autoscaling:EC2_INSTANCE_TERMINATING hook reports 'Terminating:Wait'. A heartbeat must NOT itself release the instance. For the retain-on-abandon variant the model says nothing: recorded behavior only — the recording shows an ABANDON on a terminating hook with TerminateHookAbandon=retain parking the instance in 'Terminating:Retained', still running and outside DesiredCapacity.
Emulator: no instance ever reports a :Wait state. autoscaling.lifecycle-hook-heartbeat-extends-timeout fails with "timed out waiting for two instances to reach 'Pending:Wait' (last seen matching: [])"; autoscaling.lifecycle-hook-heartbeat-timeout-extension fails with "instance paused on hook <hook-name> not met within 120s; last result: None"; autoscaling.lifecycle-hook-timeout-applies-default-result fails with "an instance paused in Pending:Wait for hook <hook-name> not met within 300s; last=None". The remaining ten checks poll the same DescribeAutoScalingGroups Instances[].LifecycleState for 'Pending:Wait'/'Terminating:Wait' with their own 240-900 s budgets and are killed by the harness at 60 s with no verdict. The group does launch instances (the companion autoscaling__events__lambda trace shows i-… launched and only an 'EC2 Instance Launch Successful' activity emitted), so the instance is advanced straight past the hook instead of being held. Consequently CompleteLifecycleAction/RecordLifecycleActionHeartbeat are never exercised against a real token, and no DefaultResult timeout ever fires.
Why: every deployment pattern built on lifecycle hooks silently degrades to no hook at all against the emulator — connection draining, instance warm-up, configuration-management bootstrap and terminate-time backup all run after the instance has already been admitted to InService or destroyed. A client that scales out and then waits for Pending:Wait to publish its action token waits forever; one that relies on ABANDON-on-timeout to reject a bad instance never sees it rejected.
Fix: the group/instance lifecycle state machine in the autoscaling service state — the reconciliation that advances an instance Pending -> Pending:Wait -> Pending:Proceed -> InService (and Terminating -> Terminating:Wait -> Terminating:Proceed) must consult the group's hook collection, mint a LifecycleActionToken per held instance, hold until CompleteLifecycleAction, reset the countdown on RecordLifecycleActionHeartbeat, and apply DefaultResult (and the retain variant) when HeartbeatTimeout/GlobalTimeout elapse. Open issue 20261111T093414Z-autoscaling-a-desiredcapacity-0-group-never-reaches-an.md describes a convergence gap on the way to InService and lists one of these check names in its own trace ids, but the replay does not report any of these fifteen checks as owned by it and it does not state the wait-state/token/heartbeat contract; it does not cover this cause.
Traces: the thirteen check ids listed above.

Cause 2 of 3: PutLifecycleHook's refusal of an invalid LifecycleTransition is emulator-worded. Failing check id: autoscaling.lifecycle-hook-create-delete-lifecycle.
AWS: the refusal message is fixed text naming the member and the two valid values: "'LifecycleTransition' must be one of: autoscaling:EC2_INSTANCE_LAUNCHING, autoscaling:EC2_INSTANCE_TERMINATING" (recorded behavior for this error class; the model carries the same value list in LifecycleHook.LifecycleTransition's documentation but no message text). The entire message is fixed text — it contains NO value taken from the request, in particular not the rejected transition string.
Emulator: it answers the same error code with a different, generated sentence that interpolates the offending value: "The LifecycleTransition value autoscaling:NOT_A_REAL_TRANSITION is not valid: it must be one of [autoscaling:EC2_INSTANCE_LAUNCHING, autoscaling:EC2_INSTANCE_TERMINATING]" (here autoscaling:NOT_A_REAL_TRANSITION is the request's value; the brackets and the leading clause are the emulator's own wording).
Why: clients and CLI users that match or log the refusal text see a message AWS never emits, and any assertion on the fixed text fails.
Fix: the PutLifecycleHook input validation/refusal path in its handler (services/service-com-amazonaws-autoscaling-autoscaling-2011-01-01/src/ops/put_lifecycle_hook.rs) must emit AWS's fixed sentence without echoing the submitted value.
Traces: autoscaling.lifecycle-hook-create-delete-lifecycle.

Cause 3 of 3: PutLifecycleHook's hook-limit refusal message is emulator-worded. Failing check id: autoscaling.put-lifecycle-hook-limit-exceeded-rejected.
AWS: once a group already holds the maximum of 50 lifecycle hooks, PutLifecycleHook is refused with LimitExceeded (Smithy LimitExceededFault, errorKind client, HTTP 400, awsQueryError code LimitExceeded, doc "You have already reached a limit for your Amazon EC2 Auto Scaling resources (for example, Auto Scaling groups, launch configurations, or lifecycle hooks)") and the message is the fixed sentence "You cannot have more than 50 hooks per Auto Scaling group" — fixed text end to end, with the limit 50 as the only number and no hook name in it.
Emulator: it serves a generated message that names the rejected hook: "The lifecycle hook <hook-name> exceeds the limit of 50 lifecycle hooks per Auto Scaling group" (<hook-name> is the request's LifecycleHookName).
Why: a client that keys on the documented limit text (or a human reading it) gets a sentence AWS does not serve; the hook name in it also makes the message look resource-specific rather than quota-specific.
Fix: the limit check in the PutLifecycleHook handler (services/service-com-amazonaws-autoscaling-autoscaling-2011-01-01/src/ops/put_lifecycle_hook.rs) must raise LimitExceededFault with AWS's fixed text.
Traces: autoscaling.put-lifecycle-hook-limit-exceeded-rejected.

## Evidence
Cause 1 — Expected (AWS): with a hook {LifecycleTransition: autoscaling:EC2_INSTANCE_LAUNCHING, HeartbeatTimeout: 30..7200, DefaultResult: CONTINUE|ABANDON} on group G, SetDesiredCapacity(G, 1) makes DescribeAutoScalingGroups(G).AutoScalingGroups[0].Instances[] report an instance with LifecycleState == 'Pending:Wait'; RecordLifecycleActionHeartbeat on that hook leaves it at 'Pending:Wait' and resets the countdown; CompleteLifecycleAction(LifecycleActionResult=CONTINUE) advances it past 'Pending:Wait' to InService; letting HeartbeatTimeout elapse applies DefaultResult instead. With a terminating hook, scale-in reports LifecycleState == 'Terminating:Wait', and under TerminateHookAbandon=retain an ABANDON leaves it 'Terminating:Retained' and running outside DesiredCapacity.
Actual (emulator): no instance is ever reported in 'Pending:Wait' or 'Terminating:Wait'. Replay details: autoscaling.lifecycle-hook-heartbeat-extends-timeout -> AssertionError: timed out waiting for two instances to reach 'Pending:Wait' (last seen matching: []); autoscaling.lifecycle-hook-heartbeat-timeout-extension -> AssertionError: instance paused on hook <hook> not met within 120s; last result: None; autoscaling.lifecycle-hook-timeout-applies-default-result -> AssertionError: an instance paused in Pending:Wait for hook <hook> not met within 300s; last=None; the other ten checks -> 'Error: Check timed out after 60.0s' while polling for the same states.

Cause 2 — Expected (AWS) message, fixed text in full: "'LifecycleTransition' must be one of: autoscaling:EC2_INSTANCE_LAUNCHING, autoscaling:EC2_INSTANCE_TERMINATING". Actual (emulator): "The LifecycleTransition value autoscaling:NOT_A_REAL_TRANSITION is not valid: it must be one of [autoscaling:EC2_INSTANCE_LAUNCHING, autoscaling:EC2_INSTANCE_TERMINATING]" — the fixed part is reworded and the request's transition value is interpolated.

Cause 3 — Expected (AWS): HTTP 400, error code LimitExceeded, message "You cannot have more than 50 hooks per Auto Scaling group" (all fixed text; 50 is the quota). Actual (emulator): message "The lifecycle hook <LifecycleHookName from the request> exceeds the limit of 50 lifecycle hooks per Auto Scaling group".

Repeat with LifecycleTransition=autoscaling:EC2_INSTANCE_TERMINATING and a scale-in for 'Terminating:Wait'.
