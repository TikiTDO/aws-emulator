=== Cause 1 of 1: the issued relay address is an AWS-form public hostname rather than the host the emulator is reached on ===
AWS: Smithy (services/service-com-amazonaws-kinesisvideosignaling-awsacuitysignalingservice/smithy-model/com-amazonaws-kinesisvideosignaling-awsacuitysignalingservice.json): GetIceServerConfig is restJson1 POST /v1/get-ice-server-config, success code 200; input ChannelARN required (ResourceARN, @length 1..1024, @pattern ^arn:aws:kinesisvideo:[a-z0-9-]+:[0-9]+:[a-z]+/[a-zA-Z0-9_.-]+/[0-9]+$) plus optional ClientId, Service (enum, only TURN), Username; output is the single member IceServerList (list of IceServer{Uris, Username @length 1..256 @pattern ^[a-zA-Z0-9_.-]+$, Password same, Ttl @range 30..86400}); IceServer$Uris is documented as "an array of URIs, in the form specified in the I-D.petithuguenin-behave-turn-uris spec", i.e. turn:/turns: URIs naming the relay a viewer must actually be able to reach. The model does not fix the host: for that part, recorded behavior only — the recording shows AWS answering 200 with one IceServer carrying Ttl 300 and turn:/turns: Uris, with Uris/Username/Password shaped-not-asserted because their concrete values are per-run and are NOT a requirement. What IS a requirement is that the address the service hands a client is an address of the service answering the call; the replay's host check is exactly that, and it is the emulator's own rule that an endpoint it advertises must be one it is reached on.
Emulator: the handler answers 200 with a well-shaped IceServerList, but every entry of Uris names a synthesized public AWS hostname of the form <channel-label>.kinesisvideo.<region>.amazonaws.com on port 443 (turn:...?transport=udp, turns:...?transport=udp, turns:...?transport=tcp). The replay verdict is mismatch with detail "$.IceServerList[0].Uris[0]: host_not_own": the emulator announced a host it does not serve and cannot be reached on, so the whole IceServerList[0] comparison fails even though status, Ttl, Username and Password are fine. The handler's own module header states the intent outright — the relay is "UNREACHABLE BY CONSTRUCTION" and the address "deliberately keeps the AWS form" — so this is a deliberate choice that the corpus rejects.
Why: a WebRTC client takes those Uris verbatim and opens a TURN/TURNS connection to them. Pointed at *.amazonaws.com, the client either resolves and dials real AWS infrastructure (traffic leaving the emulated environment entirely, against an account and a relay the test has no relationship with) or fails name resolution with no diagnosable cause; either way the TURN fallback this operation exists to provide can never be established against the emulator, while the response claims it can for the reported Ttl. A client or test that asserts the emulator is self-contained sees an off-box address handed back by an in-box call.
Fix: the address construction in this operation's handler, not its state or serializer — services/service-com-amazonaws-kinesisvideosignaling-awsacuitysignalingservice/src/ops/get_ice_server_config.rs, functions relay_host / relay_label / turn_uris, whose output is stored into IceServerRecord.uris. The host must be derived from the address the emulator is actually reached on (the same advertised-host seam kinesisvideo's GetSignalingChannelEndpoint uses to hand back a data-plane endpoint the client then succeeds against in step task#3 of this same fixture), keeping the documented turn:/turns: URI form, the transport query parameters and a port the emulator serves. Because the credential set is cached on the channel (IceServerRecord), the stored uris must be rebuilt from that seam too, so a record minted under one advertised host is not replayed under another.
