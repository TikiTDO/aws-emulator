# ListControls serves paraphrased Name/Description and synthesized CreateTime for catalog controls

> _Note: this issue was identified against the code base at commit `03940a68414c0e728665705990f1ba830338295d`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
ListControls

## Description
ListControls answers 200 and, for the controls in these clusters, even serves the catalog's OWN control ARN — so unlike the fabricated-identity issues already open, the entry is findable. What is wrong is its CONTENT: the @required Description (and, in several causes, the @required Name) carries the emulator's own paraphrase of the control instead of the text the AWS Control Catalog publishes, and CreateTime carries a synthesized timestamp (the recorded run shows a run of consecutive late-2023 day boundaries, allocated in seed order) instead of the control's actual release time. EIGHT divergence clusters are bundled here, numbered as causes below; ALL EIGHT must be closed and re-replayed before this issue is done.

Shared AWS basis (cited once, applies to every cause). Smithy model services/service-com-amazonaws-controlcatalog-controlcatalog/smithy-model/com-amazonaws-controlcatalog-controlcatalog.json — ListControls: POST /list-controls, success code 200, @readonly, paginated (inputToken/outputToken NextToken, pageSize MaxResults @range 1..100, items Controls); output ListControlsResponse.Controls @required. ControlSummary: Arn @required (ControlArn @length 34..2048, @pattern ^arn:(aws(?:[-a-z]*)?):(controlcatalog|controltower):[a-zA-Z0-9-]*::control/[0-9a-zA-Z_\-]+$), Name @required — "The display name of the control", Description @required — "A description of the control, as it may appear in the console. Describes the functionality of the control", CreateTime — "A timestamp that notes the time when the control was released (start of its life) as a governance capability in Amazon Web Services". The Control Catalog is an AWS-published, account- and region-independent read-only dataset (the ARNs carry neither account nor region), so for a given control ARN every account gets byte-identical Name, Description and CreateTime; the model fixes the field set and the recorded responses are the catalog's own content for the controls named below. No model constraint governs the wording itself, so for the exact strings this is recorded behavior only: the requirement is that the catalog's published Name/Description text and release timestamp for that ARN are served verbatim, not that any one literal below is hard-coded.

Shared Emulator basis: status matches (200) and the ARN matches, so the divergence is reported as value_mismatch on CreateTime / Description / Name of an entry inside the @required Controls list — never as missing/extra. Every reported actual CreateTime is a 2023-11/2023-12 midnight value unrelated to the control's release date, and every reported actual Description is a rewrite of the catalog sentence (typically AWS Config's "The rule is NON_COMPLIANT if ..." phrasing replaced by an emulator-authored "Detects whether ..." sentence, or vice versa).

Shared Why: Control Catalog is consumed as reference data. A client that renders or diffs a control's console description, that matches the catalog Description against a compliance framework's control text, or that uses CreateTime to decide which controls are new since its last sync, gets an answer from the emulator it cannot get from AWS: the descriptions never match the published catalog, and every control looks as if it was released in late 2023, so "controls released after <date>" and any sort or watermark on CreateTime is wrong for the whole catalog.

Shared Fix: the ControlCatalog catalog seed records this service reads (services/service-com-amazonaws-controlcatalog-controlcatalog/src/state.rs) and the ControlSummary projection in the ListControls handler (services/service-com-amazonaws-controlcatalog-controlcatalog/src/ops/list_controls.rs, documented as projecting each summary from the same stored record GetControl answers with) — Name, Description and CreateTime must be read from the catalog record rather than authored or allocated at seed time. Because GetControl projects the same record, fixing the record fixes both.
