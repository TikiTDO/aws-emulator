# SageMaker training jobs never execute: every accepted CreateTrainingJob ends Failed with no SecondaryStatus progression and no model artifact, plus no role-permission check and a GetSearchSuggestions that ignores real resources (3 causes)

> _Note: this issue was identified against the code base at commit `a348f7a60ca5edb956d11f71c3f040d86e771b20`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
CreateTrainingJob

## Description
This issue bundles THREE independent root causes on the SageMaker training surface. Each is its own work item; ALL THREE must be closed before submitting.

Service attribution: several grounding checks carry the composite leading token `s3__sagemaker` (a cross-service check id). The diverging responses in all of them come from the SageMaker control plane (CreateTrainingJob / DescribeTrainingJob / GetSearchSuggestions), so the issue is filed under `sagemaker`. Both `s3` and `sagemaker` are bootstrapped, so this attribution does not move anything past the bootstrap gate.

Related already-open issues, named here so a fixer does not re-file them and does not assume they cover these causes: 20261022T120642Z-sagemaker-createtrainingjob-stub.md (CreateTrainingJob answering 501 as a scaffold stub — it no longer does; the call is now accepted, which is why the failures below are new and carry new replay keys), 20261024T160943Z-sagemaker-runs-no-job-work-processing-pipeline-step.md (processing / pipeline-step / hyperparameter-tuning / AutoML execution — explicitly NOT the training-job execution path below), 20261022T210606Z-sagemaker-accepts-requests-real-aws-refuses-no-s3.md (S3 artifact-existence / image-URI validation), and 20261024T160943Z-sagemaker-control-plane-gaps-createuserprofile-and-deleteaibenchmarkjob-are.md (which owns the sibling check sagemaker.search-suggestions-returns-matching-property-names). None of these carries the replay keys below.

Cause 1 of 3: a training job is accepted but never runs — DescribeTrainingJob reports the terminal status Failed instead of Completed, SecondaryStatus jumps straight to Failed without passing through any active-container phase, and no model artifact is written under OutputDataConfig.S3OutputPath.
AWS: Smithy: CreateTrainingJob requires TrainingJobName/RoleArn/OutputDataConfig and returns TrainingJobArn (modeled errors ResourceInUse, ResourceLimitExceeded, ResourceNotFound, all 400). DescribeTrainingJob's output has required members TrainingJobStatus (enum InProgress|Completed|Failed|Stopping|Stopped|Deleting), SecondaryStatus (enum Starting|LaunchingMLInstances|PreparingTrainingStack|Downloading|DownloadingTrainingImage|Training|Uploading|Stopping|Stopped|MaxRuntimeExceeded|Completed|Failed|Interrupted|MaxWaitTimeExceeded|Updating|Restarting|Pending) and ModelArtifacts, whose required member S3ModelArtifacts is documented as "The path of the S3 object that contains the model artifacts. For example, s3://bucket-name/keynameprefix/model.tar.gz" — i.e. an object that EXISTS after a successful run. The model also exposes SecondaryStatusTransitions, TrainingStartTime/TrainingEndTime, TrainingTimeInSeconds/BillableTimeInSeconds and FinalMetricDataList, all of which only have values if the job ran. Recorded behavior: a well-formed job against an AWS built-in algorithm image (xgboost / linear-learner, pulled from the per-region AWS-owned ECR registry) advances InProgress -> Completed through the Starting/Downloading/Training/Uploading phases and leaves a real loadable tar archive at the reported S3ModelArtifacts URI; StoppingCondition.MaxRuntimeInSeconds caps a long job (terminal SecondaryStatus MaxRuntimeExceeded) while a twin inside the limit still reaches Completed.
Emulator: CreateTrainingJob is accepted (200, TrainingJobArn returned, job visible to DescribeTrainingJob), and the job then settles at TrainingJobStatus 'Failed' with SecondaryStatus 'Failed' and FailureReason (example text) "This emulator has no container runtime, so the training job's algorithm image was never started and no model artifacts were written to the output S3 location". No intermediate SecondaryStatus is ever observed (a poller waiting for any active-container phase sees the job leave InProgress straight into Failed), and the declared OutputDataConfig prefix stays empty, so there is no model.tar.gz at the ModelArtifacts.S3ModelArtifacts URI the emulator reports.
Why: this is the terminal status being the OPPOSITE of AWS's for a valid request, so every downstream flow is blocked at its first step rather than at the step it is testing: Model/EndpointConfig/Endpoint deploys have no artifact to serve, batch transform has no model, model packages cannot be registered from a trained artifact, inference-recommender/scaling-recommendation has no endpoint, and SecondaryStatusTransitions/MaxRuntimeInSeconds/StoppingCondition semantics are entirely unobservable. Worse for correctness testing: a job that FAILED for a real reason (bad image, denied S3, exceeded MaxRuntime) is indistinguishable from one the emulator simply did not run, because both are Failed, and a negative check's positive control can never be established — so a genuine refusal and a no-op look identical to a client.
Fix: the training-job execution path in the SageMaker control plane — CreateTrainingJob's handler and the job state machine it writes, read back by DescribeTrainingJob: drive an accepted job through the modeled SecondaryStatus phases to Completed, record SecondaryStatusTransitions/TrainingStartTime/TrainingEndTime, honour StoppingCondition.MaxRuntimeInSeconds, and materialize a model artifact object under OutputDataConfig.S3OutputPath so ModelArtifacts.S3ModelArtifacts names an object that exists.

Cause 2 of 3: CreateTrainingJob accepts a request whose RoleArn has no S3 permission on the input/output bucket, and creates the job.
AWS: recorded behavior only (the Smithy model constrains RoleArn only by pattern ^arn:aws[a-z\\-]*:iam::\\d{12}:role/?[a-zA-Z_0-9+=,.@\\-_/]+$ and models no authorization error on this operation). Recorded AWS REFUSES the call: CreateTrainingJob returns a non-2xx whose message names the denied S3 action (example stderr text contains "s3:ListBucket" / "AccessDenied" / "is not authorized"), nothing is written under the declared output prefix, and the job name does not appear in ListTrainingJobs. The requirement is the REFUSAL plus the job not being created; the exact message text is an example. The same check's positive control, an otherwise identical request whose role DOES have S3 access, is accepted and reaches Completed.
Emulator: the call succeeds (CreateTrainingJob returns 200 and the job is created) for the role with no S3 permissions, so the check's `assert not ok` fails with "expected CreateTrainingJob to reject a role with no S3 permissions, but it succeeded".
Why: a caller cannot distinguish a correctly-scoped execution role from a misconfigured one — the emulator never surfaces the permission error AWS raises at submit time, so IaC/CI that validates least-privilege roles against the emulator passes and then fails in AWS. It also makes the whole negative class untestable: there is no refusal to assert on.
Fix: the RoleArn authorization check in CreateTrainingJob's validation path — resolve the role, evaluate its policy against the S3 input channel and OutputDataConfig locations, and refuse the request naming the denied action instead of accepting it. (The already-open 20261022T210606Z-sagemaker-accepts-requests-real-aws-refuses-no-s3.md describes an adjacent family of missing pre-checks but does not carry this check's replay key; this cause is the role-permission evaluation on CreateTrainingJob specifically.)
Traces: s3__sagemaker.cli-sagemaker-missing-role-permission-negative. Handler: services/service-com-amazonaws-sagemaker-sagemaker/src/ops/create_training_job.rs.

Cause 3 of 3: GetSearchSuggestions does not derive suggestions from resources that exist in the account — a hyperparameter key that exists only because a TrainingJob was created with it is never suggested, so a client polling for it never converges.
AWS: Smithy: GetSearchSuggestions takes required Resource (enum ResourceType) plus SuggestionQuery and returns PropertyNameSuggestions (PropertyNameSuggestionList); it models NO errors, so the only observable contract is the content of that list. Recorded behavior: with Resource='TrainingJob' and SuggestionQuery.PropertyNameQuery.PropertyNameHint set to a TRUNCATED prefix of a custom hyperparameter name, AWS returns a suggestion whose PropertyName is the full lowercase-namespaced property "hyperparameters.<key>" for the key that job was actually created with — i.e. the suggestion list is computed from indexed resources, not from a fixed vocabulary, and it completes a partial hint rather than echoing a complete one.
Emulator: the suggestion never appears. The check creates the TrainingJob, then polls GetSearchSuggestions with the truncated hint; the predicate is never satisfied and the check is killed by its harness budget ("Check timed out after 60.0s"). Had the suggestion been returned, the first probe (~11 s into the check) would have satisfied it well inside the budget, so the timeout is the emulator's missing suggestion, not an under-budgeted check.
Why: any console/SDK caller using GetSearchSuggestions for property-name completion over Search/ListTrainingJobs gets an answer unrelated to its own account's resources, and a client that polls for a just-created resource's property to become searchable hangs instead of converging.
Fix: GetSearchSuggestions' handler and the searchable-property index it reads — build PropertyNameSuggestions from the stored resources of the requested Resource type (including per-resource HyperParameters and Tags under the lowercase "hyperparameters."/"tags." namespaces) and match PropertyNameHint as a prefix rather than returning a static or empty list. Note the sibling check sagemaker.search-suggestions-returns-matching-property-names is owned by 20261024T160943Z-sagemaker-control-plane-gaps-createuserprofile-and-deleteaibenchmarkjob-are.md; this cause is the resource-derived indexing that check's replay key does not cover.
Traces: sagemaker.get-search-suggestions-reflects-existing-resources. Handler: services/service-com-amazonaws-sagemaker-sagemaker/src/ops/get_search_suggestions.rs, .../src/state.rs.
