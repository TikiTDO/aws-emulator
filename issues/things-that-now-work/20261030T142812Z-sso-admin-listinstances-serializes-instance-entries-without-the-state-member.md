# ListInstances serializes instance entries without the State member on the edge-case instance listing

> _Note: this issue was identified against the code base at commit `6d14a9a831b2c017b564e34b5138bca4659f1a33`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
ListInstances

## Description
ONE cause: the shared Identity Center instance serializer used by ListInstances never emits the instance's `State` view, so every listed instance is served without it.

Cause 1 of 1: ListInstances entry omits State (fixture sso-admin-describe-list-edge-cases-r2, step task#4).
AWS: ListInstances returns `Instances`, a list of instance metadata entries (Smithy: ListInstances -> ListInstancesResponse.Instances targets InstanceList @length min 0 max 10, paginated with NextToken/MaxResults; member shape com.amazonaws.ssoadmin#InstanceMetadata carries InstanceArn, IdentityStoreId, IdentityStoreArn, OwnerAccountId, Name, CreatedDate, Status (enum InstanceStatus), StatusReason, PrimaryRegion, Regions). Recorded behavior only: in addition to the modeled members, each served entry carries a `State` structure whose `Name` is the instance's lifecycle status, i.e. `State: {"Name": <instance status>}` sitting beside the flat `Status` with the same enum value (`ACTIVE` for an active instance). The on-disk model has no State member on InstanceMetadata, so the recording is the authority for this member; the rule is that State.Name mirrors the instance's own Status. The entry's identity values (InstanceArn, Name, IdentityStoreId/IdentityStoreArn, CreatedDate) are read from the instance being listed and are per-run values, not requirements.
Emulator: HTTP 200 whose listed instance matches on every other member but has no State at all - the replay reports `$.Instances[Name="<instance name>"].State: missing (expected {'Name': 'ACTIVE'}, got None)`. In this run the instance name happened to be the generated `sim2real-wire-idc-6dab9b7f`; that generated name is a per-run value and only the absent State member is the defect.
Why: a client that reads an instance's lifecycle from the State view this API serves - filtering a listing for State.Name == ACTIVE, or polling a listing while an instance moves through CREATE_IN_PROGRESS - finds the member absent on every entry, so it either dereferences a missing field or concludes no instance is ready and waits forever. The flat Status is present, so the failure is silent rather than an obvious error.
Fix: the shared InstanceMetadata response serializer used by ListInstances - populate State from the same instance record the flat Status is read from, so State.Name equals Status.
Traces: sso-admin-describe-list-edge-cases-r2#task#4.
