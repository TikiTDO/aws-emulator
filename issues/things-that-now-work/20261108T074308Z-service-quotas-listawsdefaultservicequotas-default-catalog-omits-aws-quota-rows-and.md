# ListAWSDefaultServiceQuotas default catalog omits AWS quota rows and re-authors quota metadata for cognito-identity, cognito-idp, comprehend, dax, directconnect, dms, docdb and quicksight

> _Note: this issue was identified against the code base at commit `99dd7eb41b296722799c7b8575de84efccd4dcdf`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
ListAWSDefaultServiceQuotas

## Description
This issue bundles 8 net-new causes, all of them the same emulator fault seen on eight different ServiceCodes: the default-quota catalog that ListAWSDefaultServiceQuotas serves is a hand-authored table. For these ServiceCodes it (a) holds only a small fraction of the quota rows AWS publishes, so most QuotaCodes are absent from the listing altogether, and (b) for the rows it does hold it re-words Description, flips Adjustable, re-words ServiceName, changes Value and drops the optional Period / UsageMetric / QuotaContext sub-structures. Every step answers HTTP 200 with a well-formed ListAWSDefaultServiceQuotasResponse, so the divergence is entirely in the catalog data.

Shared model basis for all 8 causes — Smithy: ListAWSDefaultServiceQuotas(ServiceCode required, @length 1..63, @pattern ^[a-zA-Z][a-zA-Z0-9-]{1,63}$) -> ListAWSDefaultServiceQuotasResponse{Quotas: ServiceQuotaListDefinition, NextToken}, paginated(items=Quotas, pageSize=MaxResults); ServiceQuota members ServiceCode, ServiceName, QuotaArn, QuotaCode, QuotaName, Value (QuotaValue double, @range 0..1e10), Unit, Adjustable (boolean, 'Indicates whether the quota value can be increased'), GlobalQuota, UsageMetric (MetricInfo), Period (QuotaPeriod), QuotaContext (QuotaContextInfo), Description (@length 0..350). The model fixes the shape of a row but not its content, so the per-ServiceCode default catalog is recorded behavior only: AWS returns, for a ServiceCode, the complete set of that service's default quotas with AWS's own QuotaName/Description/Value/Unit/Adjustable/GlobalQuota and, where the quota has them, Period, UsageMetric and QuotaContext. The recordings below are the reference for that content.

Cause 1 of 8 — ServiceCode cognito-identity (fixture service-quotas-catalog-list-aws-default-service-quotas-cognito-identity, step task#1).
AWS: recorded behavior only — the listing contains the Cognito Federated Identities default rows, among them L-E97D135E 'Rate of GetOpenIdToken requests' (Adjustable true, Value 200, Unit None, GlobalQuota false, QuotaArn arn:aws:servicequotas:<region>::cognito-identity/L-E97D135E), L-A38ADA84 'Rate of GetId requests' (Value 25), L-5AE9F13D 'Rate of GetCredentialsForIdentity requests' (Value 200), L-DAF3EAFF 'Rate of TagResource requests' (Value 5), L-EAF710D2 (Adjustable false), plus L-14403AD5, L-1F1BC060, L-29CA570C, L-8692CE1C and L-B08F14B9. Each Description is AWS's own text, e.g. 'The maximum number of GetOpenIdToken requests that you can make per second.'
Emulator: answers 200 but Quotas contains none of those ten QuotaCodes — the replay reports every one of them as `missing (... got None)`.
Why: a client enumerating a service's default quotas (console, quota-increase tooling, any ListAWSDefaultServiceQuotas-then-RequestServiceQuotaIncrease flow) cannot discover these quotas at all, so it concludes the quota does not exist for cognito-identity.
Fix: the service-quotas crate's default-quota catalog data that the ListAWSDefaultServiceQuotas handler reads, not the handler's pagination.
Traces: service-quotas-catalog-list-aws-default-service-quotas-cognito-identity#task#1.
